# Nota MVP 需求说明

## 1. 目标

用尽可能少的代码完成一条可现场演示的语音处理链路：Hardware Simulator 录音并上传，Next.js 服务创建异步任务，依次完成 ASR、文本校准和 Agent 处理，再通过 MQTT 通知客户端拉取结果。

第一版只验证技术闭环和讲解效果，不以生产级健壮性为目标。

## 2. 交付范围

### 2.1 Next.js Web 与服务端

- Web 页面展示任务列表、当前处理阶段、转写结果、摘要和 Agent 工具调用记录。
- HTTP API 接收音频、创建任务、查询任务和查询剩余额度。
- 后台 Worker 处理任务，不让上传请求等待 ASR 和 AI 完成。
- 本地数据持久化，重启服务后仍能看到已创建任务。
- MQTT 发布任务状态；消息只负责通知，完整结果仍通过 HTTP 查询。

### 2.2 Flutter 用户 App

- 查看录音任务列表和详情。
- 订阅 MQTT 任务状态并刷新页面。
- MQTT 断开或 App 回到前台时，通过 HTTP 重新查询任务状态。
- 查看转写、校准文本、摘要、待办、提醒和 Agent 调用过程。

### 2.3 Flutter Hardware Simulator

- 使用手机麦克风开始和停止录音。
- 将音频和最少的元数据上传到 Next.js API。
- 显示服务端返回的 `taskId`。
- 订阅该任务的 MQTT Topic，展示处理阶段。
- 失败时显示错误，用户可以重新录音并重新开始。

### 2.4 AI 处理链路

任务按以下顺序处理：

1. 保存音频并创建任务。
2. 音频预处理占位，第一版不实现复杂降噪算法。
3. 调用可配置的 ASR，将音频转成文字。
4. 调用可配置的语言模型校准明显错词。
5. Agent 根据文本自主选择工具。
6. 校验结果结构并保存。
7. 核销额度并通过 MQTT 通知客户端。

Agent 至少提供以下三个工具，演示时保证一次任务能触发两个或以上工具：

- `createTodo`：创建待办事项。
- `setReminder`：保存提醒时间和内容，不接入系统日历。
- `searchHistory`：查询历史录音及摘要。

界面必须展示 Agent 选择了什么工具、传入什么参数以及工具返回结果。

## 3. AI 与 ASR 配置

- 服务端提供一个集中配置文件，并从 `.env.local` 读取 API 地址、API Key、Chat Model 和 ASR Model。
- 模型适配层使用 OpenAI Compatible 风格接口，方便后续替换为其他支持 Function Calling 的模型。
- 默认启用 Mock 模式，无需 Key 也能在 localhost 跑通全部页面和状态流。
- 真实模式没有配置完整时直接报错，不自动猜测模型或供应商。

## 4. Free 用户每日 10 次额度

- 第一版只有一个演示用户。
- 每次创建任务时预占一次当日额度，防止同时提交超过 10 次。
- 整条链路成功后正式核销。
- 任务最终失败时释放预占额度。
- ASR 或 AI 的内部调用次数不等于用户次数，重试不重复扣额度。
- 相同 `requestId` 返回原任务，避免重复提交导致重复扣费。

## 5. Happy Path

1. 启动 MQTT Broker、Next.js 服务和 Worker。
2. 打开 Hardware Simulator 并录音。
3. Simulator 通过 HTTP 上传音频，服务端立即返回 `taskId`。
4. Worker 依次执行音频处理、ASR、校准、Agent 工具调用和结果校验。
5. 每个阶段写入数据库并发布 MQTT 状态。
6. Flutter App 或 Web 收到通知后，用 HTTP 获取最新结果。
7. 用户看到转写、摘要、待办、提醒、工具调用过程和剩余额度。

## 6. 错误处理原则

第一版不实现复杂补偿流程。任何阶段失败时：

- 任务标记为 `FAILED` 并记录可阅读的错误信息。
- 释放已预占额度。
- MQTT 发布失败状态。
- 客户端提示用户重新录音或重新提交。

不实现跨步骤恢复、供应商自动切换、死信队列和复杂重试策略。

## 7. 非目标

- 不做历史数据 backfill 或旧系统迁移。
- 不做生产部署、高可用、集群、容灾和性能压测。
- 不接入真实硬件、蓝牙配网、SIM 卡和固件升级。
- 不做复杂降噪、说话人识别和多语言路由。
- 不接入手机系统日历或系统提醒。
- 不做支付、完整账号系统和多租户权限。
- 不做语义向量库；历史查询先使用简单文本检索。
- 不覆盖大量 bad flow；错误统一失败并让用户重新开始。

## 8. 验收标准

- localhost 环境能完成一次从录音上传到结果展示的完整流程。
- Web、用户 App 和 Hardware Simulator 职责清晰，组件没有集中在单一文件。
- Agent 能自主选择并调用至少两个工具，调用过程在界面可见。
- 第 11 次任务被拒绝；失败任务不占用次数；重复请求不重复扣费。
- Mock 模式可以演示，填写服务端配置后可以切换到真实 ASR 与 AI。
- README 能说明运行步骤、架构和关键取舍。
